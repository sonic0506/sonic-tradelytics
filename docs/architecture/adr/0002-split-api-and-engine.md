# ADR-0002. api와 매매 engine을 별도 프로세스로 분리

- 상태: 제안
- 날짜: 2026-10-26

## 맥락

매매 루프는 장중에 멈추면 안 되고, 웹 요청 처리(배포, 무거운 집계 쿼리, 오류)가 매매에 영향을 주면 안 돼요. 반대로 엔진 재시작이 화면 접근을 막아도 안 돼요.

또 토스 API는 **클라이언트당 유효 토큰이 1개**라, 두 프로세스가 각자 토큰을 발급하면 서로의 토큰을 무효화해요. 웹소켓도 계정당 동시 연결이 2개뿐이에요([연동 문서](../../integrations/toss-securities-api.md#인증)).

## 결정

한 코드베이스(`apps/server`)에 진입점 두 개를 둬요.

- `engine`: BotRunner, Scheduler, TossClient, Notifier. 토스 API를 호출하고 토큰을 발급하는 유일한 프로세스
- `api`: 화면용 조회, 봇 설정 저장, 명령 접수. 토스 API를 직접 호출하지 않음

두 프로세스는 PostgreSQL로만 소통해요 ([ADR-0004](./0004-postgres-notify-for-commands.md)).

## 결과

- 웹 배포·장애가 매매에 영향을 주지 않아요
- 호출 한도를 engine 하나가 관리하므로 한도 계산이 단순해요
- 토큰과 웹소켓 연결이 engine 한 곳에만 있어 서로 끊는 일이 없어요
- engine은 동시에 하나만 띄워요(중복 실행 방지 잠금 필요)
- 감수: 화면의 계좌 잔고는 engine이 동기화한 DB 값이라 몇 초 늦을 수 있어요

## 검토한 대안

- 단일 프로세스: 가장 단순하지만 웹 오류·배포가 매매를 끊어요
- 마이크로서비스 여러 개: 1인 운영에 비해 과해요
