# ADR-0005. 개발 점검용 모의 체결은 자체 구현, 규칙은 순수 함수로 공유

- 상태: 제안
- 날짜: 2026-10-26 (2026-10-27 수정: 사용자용 모의 모드 제거, [Q-018](../../project/open-questions.md#q-018))

## 맥락

사용자용 모의 모드는 없고, 새 봇은 소액 상한으로 실제 매매하며 검증해요([G4](../../product/prd.md#2-목표와-비목표)). 하지만 가장 큰 위험인 코드 오류로 인한 주문 반복은 실제 돈을 넣기 전에 잡아야 해요. 토스증권 공식 문서에는 API용 모의투자(샌드박스) 환경이 없어요(2026-10-26 확인). 그래서 개발자가 실시간 시세로 엔진을 점검할 모의 체결이 필요해요. 점검과 실전의 판단이 다르면 점검이 의미 없어요.

## 결정

- 규칙 평가는 `evaluate(type, params, snapshot)` 순수 함수로 만들고, 실전·개발 점검·백테스트가 그대로 같이 써요
- 주문 집행만 `Broker` 구현 두 개로 나눠요: `TossBroker`(실전), `PaperBroker`(개발 점검, 사용자 화면에 노출하지 않음)
- PaperBroker는 실시간 호가 기준으로 체결하고, 기본 슬리피지 1틱과 `fee_schedules`의 수수료·세금을 넣어요. 수수료율은 토스 `GET /api/v1/commissions` 값으로 채워요
- PaperBroker는 실제 계좌 잔고가 아니라 점검용으로 정한 금액 안에서만 체결하고, 기록은 운영 데이터와 섞지 않아요
- PaperBroker도 실전 규칙을 흉내 내요: 같은 종목 반대 방향 미체결 시 거부, 상·하한가 밖 가격 거부, `DAY` 주문은 정규장 종료 시 미체결 취소

## 결과

- 점검과 실전에서 바뀌는 것은 Broker 하나뿐이에요
- 같은 함수에 과거 시세를 넣으면 백테스트가 돼요
- 감수: 모의 체결은 실제보다 낙관적이라 전략 검증에는 쓰지 않아요. 전략 검증은 소액 검증 구간(POL-RISK-13)이 맡아요

## 검토한 대안

- 증권사 모의투자 서버 사용: 토스 Open API에는 제공되지 않아요
