# ADR-0007. 시세는 공용 수집기 한 곳에서 웹소켓으로 받아 봇들이 공유

- 상태: 제안
- 날짜: 2026-10-26 (공식 문서 확인 후 웹소켓 기준으로 갱신)

## 맥락

토스 API는 REST 호출이 그룹별 초당 한도로 묶여 있고(예: `MARKET_DATA` 초당 15회), 실시간 시세는 웹소켓으로 제공해요. 웹소켓은 **계정당 동시 연결 2개, 연결당 구독 100건**, 시세 프레임은 유실될 수 있어요(LOSSY, sequence 없음). 자세한 수치는 [연동 문서](../../integrations/toss-securities-api.md#웹소켓)에 있어요.

봇마다 시세를 따로 받으면 연결·구독·호출이 봇 수에 비례해 늘어 바로 한도를 넘어요.

## 결정

- engine 안의 `MarketCollector` 하나가 웹소켓 연결 **1개**를 열고, 모든 봇이 관심 있는 종목의 `trade:kr`·`orderbook:kr`과 계좌의 `personal:order`를 구독해요. 나머지 1개 연결은 예비로 남겨요
- 수집한 시세는 종목별 메모리 스냅샷으로 제공해요. 봇은 API를 직접 부르지 않고 스냅샷만 읽어요
- 구독 목록은 봇들의 관심 종목을 합쳐 선언해요(선언형, 전체 교체). 100건을 넘으면 우선순위가 낮은 종목은 REST 폴링으로 내려요
- 분봉·일봉·순위·지수처럼 웹소켓에 없는 데이터는 REST로 주기 조회해요. `TossClient`가 그룹별 토큰 버킷으로 속도를 제한하고, 한도가 모자라면 기다리지 않고 해당 주기의 판단을 건너뛰고 기록해요([NFR-03](../../product/prd.md#7-비기능-요구사항))
- 시세 유실에 대비해, 스냅샷마다 마지막 수신 시각을 두고 일정 시간 이상 갱신이 없으면 REST로 보정하거나 그 종목 판단을 멈춰요
- 60초마다 `PING`을 보내고, 끊기면 재연결·재선언 후 `GET /api/v1/orders`로 주문 상태를 재동기화해요

## 결과

- 같은 종목을 여러 봇이 봐도 구독은 한 번이에요
- 실시간 체결이 들어와 스캘핑 같은 짧은 주기 판단이 기술적으로 가능해요
- 연결·구독·호출 한도 관리가 한 곳에 모여요
- 감수: 시세 프레임 유실을 감지할 방법이 없어요. 체결 틱으로 VWAP 등을 계산할 때 오차가 생길 수 있어, 분봉 REST 값으로 주기적으로 보정해요
- 감수: 구독 100건이 동시에 감시할 수 있는 종목 수의 상한이에요(체결+호가면 50종목)

## 검토한 대안

- 봇별 직접 호출·연결: 계정당 연결 2개라 봇 3개부터 불가능해요
- REST 폴링만 사용: `MARKET_DATA` 초당 15회로는 감시 종목 수와 주기가 크게 제한돼요
