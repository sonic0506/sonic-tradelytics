# 13. 외부 데이터: 공식 API 숫자만 vs 뉴스 API vs LLM 요약

> 상태: 초안 · 담당: @소닉 · 최종 수정: 2026-10-27 · 상위: [기술 선택 학습 자료](./README.md)
> 관련 결정: [ADR-0008](../architecture/adr/0008-external-data-numeric-only.md) · [Q-017](../project/open-questions.md#q-017) · [DART 연동](../integrations/dart-open-api.md)

## 한 줄 요약

판단 조건에는 **공식 API로 받아 숫자·코드로 바꿀 수 있는 데이터**만 써요. 공시는 DART의 유형 코드, 해외 증시는 토스의 미국 ETF 시세예요. 뉴스와 LLM 요약은 쓰지 않아요.

## 먼저 알아둘 용어

| 용어 | 무엇인가 |
| --- | --- |
| DART Open API | 금융감독원 전자공시 시스템의 공식 API. 공시 목록과 유형 코드를 줘요 |
| 뉴스 검색 API | 키워드로 기사 목록을 찾는 API (포털 검색 API 등) |
| LLM 요약 | 언어 모델이 웹 검색 결과나 기사를 읽고 요약·판단하는 것 |
| 재현성 | 같은 입력으로 다시 계산하면 같은 결과가 나오는 성질. 채점과 검증의 전제 |
| 보수적 기본값 | 데이터를 못 받으면 위험이 있는 쪽으로 가정하는 것 |

## 우리가 풀어야 하는 문제

- 이월 봇의 장전 점검은 밤사이 공시·해외 증시·시초가 예상을 봐야 해요
- 모든 판단은 근거 카드에 남고 **나중에 채점**돼요. 근거가 재현돼야 해요
- 외부 연동이 늘수록 장애 지점도 늘어요

## 선택지 비교

| 방식 | 판단 재료 | 재현성 | 운영 부담 | 우리 상황 |
| --- | --- | --- | --- | --- |
| **공식 API의 숫자·코드 (DART 유형 코드, 토스 ETF 시세)** | 제한적 | 높음 | DART 연동 1개 추가 | 채택 |
| 뉴스 API로 기사 수 지표화 | 넓음 | 숫자는 남지만 호재·악재 구분 못 함 | 연동 추가 | 근거로 약해요 |
| LLM 웹 검색 요약으로 판단 | 가장 넓음 | 낮음 (매번 결과가 다름) | 비용·지연·장애 | 채점·검증 불가 |
| 예상 체결가 직접 계산 | 시초가 예측 | 근거 문서 없음 | 틀려도 알기 어려움 | NXT 프리마켓 가격과 실제 시초가로 대체 |

## 선택과 이유

근거가 숫자·코드로 남아야 예측을 채점하고 규칙을 고칠 수 있어요. 이 서비스의 핵심("검증 가능한 봇")을 지키는 선택이에요. 데이터를 못 받으면 경계가 있는 것으로 봐요.

## 감수한 것

- 공시 없는 이슈(업황 뉴스, 루머)는 판단에 들어가지 않아요. 가격 움직임으로만 반영돼요
- 호재 공시에도 보수적으로 움직여요

## 다시 검토할 때

- 채점 결과 공시 경계가 기회를 너무 많이 놓치면: 공시 유형을 세분화
- AI 해설(백로그 10번)은 판단이 아니라 화면 참고 정보로만
