# 09. 모의 체결: 자체 PaperBroker vs 증권사 모의서버 vs 사용자용 모의 모드

> 상태: 초안 · 담당: @소닉 · 최종 수정: 2026-10-27 · 상위: [기술 선택 학습 자료](./README.md)
> 관련 결정: [ADR-0005](../architecture/adr/0005-in-house-paper-broker.md) · [Q-018](../project/open-questions.md#q-018) · [검증 구간](../policy/risk-management.md#9-검증-구간과-상한-해제-pol-risk-13)

## 한 줄 요약

사용자용 모의 모드는 없애고, **개발 점검용 PaperBroker**만 자체 구현해요. 실전과 점검은 같은 규칙 함수를 쓰고, 주문 집행(Broker)만 바꿔 끼워요.

## 먼저 알아둘 용어

| 용어 | 무엇인가 |
| --- | --- |
| 페이퍼 트레이딩 | 실제 돈 없이 가상으로 주문·체결해 보는 것 |
| 샌드박스 | 외부 서비스가 제공하는 테스트용 환경. 토스 Open API에는 없어요 |
| 슬리피지 | 주문한 가격과 실제 체결 가격의 차이 |
| 순수 함수 | 같은 입력이면 항상 같은 출력, 외부 상태를 바꾸지 않는 함수. 테스트·재사용이 쉬워요 |
| 포트와 어댑터 (헥사고날) | 핵심 로직은 인터페이스(포트)에만 의존하고, 실제 연결(어댑터)을 바꿔 끼우는 구조. `Broker` 인터페이스에 TossBroker·PaperBroker |

## 우리가 풀어야 하는 문제

- 가장 큰 위험(주문 반복 버그)을 **실제 돈을 넣기 전에** 잡아야 해요
- 토스에는 샌드박스가 없어요
- 점검과 실전의 판단 코드가 다르면 점검이 의미 없어요

## 선택지 비교

| 방식 | 장점 | 단점 | 우리 상황 |
| --- | --- | --- | --- |
| 증권사 모의투자 서버 | 실제와 가까운 체결 | 토스 Open API에 없음 | 불가 |
| **자체 PaperBroker (개발 점검용)** | 실시간 시세로 엔진 전체를 돈 없이 돌려봄 | 체결이 실제보다 낙관적 | 채택. 엔진 동작 점검에만 |
| 사용자용 모의 모드 (가상 투자금) | 전략을 공짜로 검증 | 가상·실제 돈 혼동, 전환 절차, 규칙 바꿀 때마다 재검증 대기 | Q-018에서 제거. 소액 검증 구간으로 대체 |
| 모의 없이 바로 실전 | 가장 단순 | 엔진 버그가 첫 실제 주문에서 드러남 | 위험 |

## 선택과 이유

- `evaluate(type, params, snapshot)` 순수 함수를 실전·점검·백테스트가 같이 써요
- PaperBroker는 실시간 호가, 슬리피지 1틱, 수수료·세금, 반대 방향 미체결 거부, 상하한가 거부까지 실전 규칙을 흉내 내요
- 전략 검증은 PaperBroker가 아니라 실제 소액 매매(검증 구간)가 맡아요

## 감수한 것

- PaperBroker를 실전 규칙과 맞게 계속 유지해야 해요. 토스 규칙이 바뀌면 같이 고쳐야 해요
- 전략 검증에 실제 돈(상한 안)이 들어요

## 다시 검토할 때

- 토스가 샌드박스를 제공하면: PaperBroker 대신 쓸 수 있는지 비교
