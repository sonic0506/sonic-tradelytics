# 11. 알림 채널: 텔레그램 vs 카카오톡 vs 웹 푸시

> 상태: 초안 · 담당: @소닉 · 최종 수정: 2026-10-27 · 상위: [기술 선택 학습 자료](./README.md)
> 관련 결정: [ADR-0001](../architecture/adr/0001-tech-stack.md) · [리스크 관리 §8 알림](../policy/risk-management.md#8-알림-대상-pol-risk-12) · R-013

## 한 줄 요약

알림은 **텔레그램 Bot API**로 시작하고, 카카오톡·푸시는 필요해지면 추가해요.

## 먼저 알아둘 용어

| 용어 | 무엇인가 |
| --- | --- |
| Telegram Bot API | 봇 토큰 하나로 HTTP 요청을 보내 메시지를 전송하는 텔레그램 공식 API |
| 카카오톡 메시지 API (나에게 보내기) | 카카오 로그인 토큰으로 내 카카오톡에 메시지를 보내는 API. 토큰 갱신이 필요해요 |
| 카카오 알림톡 | 기업이 고객에게 보내는 정보성 메시지. 비즈니스 채널과 발송 대행사 계약이 필요해요 |
| 웹 푸시 | 브라우저의 서비스 워커로 받는 알림. HTTPS와 구독 관리가 필요하고, iOS는 홈 화면에 추가한 웹앱에서만 받아요 |
| 이메일·SMS | 확실하지만 느리거나(이메일) 비용이 들어요(SMS) |

## 우리가 풀어야 하는 문제

- 손절·한도 도달·오류·킬 스위치를 **휴대폰에 즉시** 알려야 해요
- 1인용, 비용과 설정이 적어야 해요
- 관리 화면은 외부에 열지 않아요 ([10](./10-deploy-and-access.md))

## 선택지 비교

| 방식 | 장점 | 단점 | 우리 상황 |
| --- | --- | --- | --- |
| **텔레그램 봇** | 무료, HTTP 요청 하나, 토큰 만료 없음 | 텔레그램 앱 설치 필요 | 채택 |
| 카카오톡 나에게 보내기 | 이미 쓰는 메신저 | OAuth 토큰 주기적 갱신 필요 | 나중에 추가 후보 |
| 카카오 알림톡 | 공식 정보성 메시지 | 사업자·채널·대행사 필요 | 1인용에 맞지 않아요 |
| 웹 푸시 | 우리 앱에서 바로 | 서비스 워커·HTTPS·구독 관리, iOS 제약, 사설망 안에서만 동작 | 구현 부담 큼 |
| 이메일 | 기록 남음 | 늦게 확인됨 | 장중 긴급 알림에 부적합 |

## 선택과 이유

가장 적은 코드로 확실하게 휴대폰에 도착해요. 서버에서 밖으로 나가는 요청만 있어서 외부에 포트를 열 필요도 없어요.

## 감수한 것

- 텔레그램 장애나 토큰 문제로 알림이 안 가도 매매는 계속돼요. **알림 실패 자체를 기록**하고, 반복되면 신규 진입을 멈추는 방안을 검토해요
- 알림에서 바로 조작(버튼으로 정지)까지 하면 편하지만, 그만큼 보안 경로가 늘어요. 지금은 알림만 보내고 조작은 관리 화면에서 해요
