# 리스크 관리 정책

> 상태: 초안 · 담당: @소닉 · 최종 수정: 2026-10-29
> 관련: [F1 봇 설정](../product/features/f1-bot-setup.md) · [자금 배분](./fund-allocation.md) · [프로젝트 리스크](../project/risks.md)

가장 큰 위험은 **코드 오류로 의도치 않은 주문이 반복되는 것**이에요. 그래서 이 정책은 수익 로직보다 먼저 구현하고, 모든 봇에 필수로 적용해요. 손실 기준 금액은 언제나 해당 봇의 **확정 투자금**이에요.

## 1. 투자 성향별 손실 중지 (POL-RISK-01)

봇을 만들 때 공격적·중립·소극적 중 하나를 고르면 유형에 맞는 손실 중지 %가 자동으로 들어가고, 숫자는 직접 바꿀 수 있어요.
예) 투자금 10만 원, 하루 -3%면 3,000원 손실 시 중지.

| 봇 유형 | 공격적 (하루 · 누적) | 중립 (하루 · 누적) | 소극적 (하루 · 누적) |
| --- | --- | --- | --- |
| 스캘핑 | -5% · -15% | -3% · -10% | -2% · -6% |
| 데이 트레이딩 | -6% · -15% | -4% · -10% | -2% · -6% |
| 스윙 | 종목당 -7% · -15% | 종목당 -5% · -10% | 종목당 -3% · -5% |
| 종가 베팅 | 1회 -5% · -15% | 1회 -3% · -10% | 1회 -2% · -6% |

- 스윙은 하루 단위 대신 **종목당 손절**, 종가 베팅은 **1회 진입당 손실**로 봐요
- 위 숫자는 시작용 예시이며, 검증 구간(POL-RISK-13) 결과를 보고 조정해요
- 손실 계산에는 실현 손익 + 보유분 평가 손익을 모두 넣어요(수수료·세금 차감 후)
- 투자금을 다시 정하면([POL-FUND-12](./fund-allocation.md#검증-구간-봇)) 손실 한도 금액은 새 확정 투자금 기준으로 다시 계산하고, 하루·누적 손익 기록은 이어서 써요

## 2. 한도 도달 시 동작

| ID | 상황 | 동작 |
| --- | --- | --- |
| POL-RISK-02 | 하루 한도 도달 | 그날 신규 진입 중단. 보유분은 설정값(즉시 청산 / 유지)대로 처리. 다음 거래일 자동 재개 |
| POL-RISK-03 | 누적 한도 도달 | 봇 종료. 보유분 청산 후 남은 투자금은 운용 자산으로 반환 ([POL-FUND-06](./fund-allocation.md)) |
| POL-RISK-04 | 연속 손절 N회 | 봇 일시 정지 + 알림. 사람이 재개해야 다시 동작. N 기본값 3 (제안) |

## 3. 성향이 바꾸는 다른 기본값 (POL-RISK-05)

성향은 손실 한도 외에 **1회 주문 비중**과 **동시 보유 종목 수** 기본값도 함께 바꿔요. 공격적일수록 크게 잡아요. 구체 값은 각 봇 도입 시 [F1 유형별 규칙](../product/features/f1-bot-setup.md#유형별-규칙-기본값-제공-사용자는-숫자만-조정)과 함께 정해요.

## 4. 진입 금지 (POL-RISK-06)

다음 종목에는 신규 진입하지 않아요. 판별 방법은 [연동 문서](../integrations/toss-securities-api.md#매수-유의사항거래-제한-판별)를 따라요.

- VI(변동성 완화장치) 발동 중
- 투자경고·투자위험·단기과열 지정
- 정리매매, 거래정지
- 매수 유의사항에 처음 보는 유형이 있는 종목 (모르면 막음)
- 관리종목은 API로 판별할 수 없어 MVP에서는 거르지 않아요. 종목 필터의 시가총액·거래대금 하한으로 일부 보완하고, 외부 수집은 [백로그](../project/roadmap.md#백로그)로 미뤄요 ([Q-012](../project/open-questions.md#q-012))

## 4-1. 매매 시간 (POL-RISK-15)

봇은 **KRX 정규장(09:00~15:30) 안에서만** 주문해요. NXT 프리마켓·애프터마켓에는 주문하지 않아요 ([Q-013](../project/open-questions.md#q-013)).

- 봇 운영 시간은 정규장 안에서만 설정할 수 있어요. 시각은 장 운영 캘린더 기준이라 개장 지연·단축 운영일도 따라가요
- 당일 청산 봇(스캘핑·데이 트레이딩)은 정규장 종료 전 설정한 청산 시각까지 전량 청산해요
- 이월 봇(스윙·종가 베팅)은 정규장 밖에 주문하지 않아요. 밤사이 변동은 장전 점검과 정규장 개시 후 손절 조건주문으로 대응해요 ([재평가 정책](./position-reevaluation.md))
- 이유: 손절 조건주문이 KRX 정규장에서만 발동해서, 정규장 밖에 주문하면 안전망 없이 포지션이 바뀌어요

## 5. 주문 폭주 방지

| ID | 정책 |
| --- | --- |
| POL-RISK-07 | 모든 봇 주문은 고유한 `clientOrderId`(= 판단 기록 id, UUID 36자)를 가져요. 토스의 중복 방지는 10분만 유효하므로, 10분이 지난 재시도는 먼저 주문 조회로 이미 접수됐는지 확인해요 |
| POL-RISK-08 | 봇별 분당 주문 횟수 상한과 계좌 전체 일일 주문 횟수 상한을 둬요. 넘으면 해당 봇을 일시 정지하고 알려요. 토스는 단시간 대량 주문을 어뷰징으로 보고 매매를 제한하므로, 상한은 그보다 충분히 낮게 잡아요 |
| POL-RISK-09 | 검증 구간(POL-RISK-13)의 봇은 투자금 상한을 강제해요 (예: 10만 원). 설정 투자금이 더 커도 상한까지만 확정해요 |

## 5-1. 종목 잠금 (POL-RISK-16)

국내 주식은 같은 종목에 반대 방향 미체결 주문이 있으면 새 주문이 거부돼요(`409 opposite-pending-order-exists`). 그래서 **한 종목은 한 시점에 한 봇만** 다뤄요 ([Q-014](../project/open-questions.md#q-014)).

1. 봇은 진입 주문 전에 그 종목의 잠금을 얻어요. 다른 봇이 잡고 있으면 진입하지 않고 "건너뛴 판단"(사유: 종목 잠금)으로 기록해요
2. 잠금은 포지션 전량 청산, 미체결 주문 취소, 손절 조건주문 정리가 모두 끝난 뒤 풀어요
3. **직접 거래 미체결 주문**이 있는 종목에는 봇이 신규 진입하지 않아요. 직접 **보유**만 있는 종목은 진입할 수 있고 수량은 나눠 기록해요 ([F4](../product/features/f4-manual-trades.md))
4. 409를 받으면 재시도하지 않고 기록해요. 청산 매도가 409로 막히면(예: 직접 매수 미체결 때문) 즉시 알리고, 사람이 그 미체결 주문을 정리하게 해요
5. 개발 점검용 PaperBroker도 같은 잠금과 409 규칙을 따라요 ([ADR-0005](../architecture/adr/0005-in-house-paper-broker.md))

## 6. 수동 제어 (POL-RISK-10)

| 제어 | 범위 | 동작 |
| --- | --- | --- |
| 봇 일시정지 | 봇 1개 | 신규 진입 중단, 보유분 유지 |
| 봇 즉시 전량 청산 | 봇 1개 | 미체결 취소 + 보유분 시장가 청산 |
| 킬 스위치 | 모든 봇 | 모든 봇 즉시 정지 + 미체결 주문 취소. 선택 시 전량 청산. 1초 안에 신규 주문 0건 ([NFR-02](../product/prd.md#7-비기능-요구사항)) |

## 7. 장애 시 동작 (POL-RISK-11)

- 시세·잔고를 못 받거나, 판단 기록 저장에 실패하거나, 재평가 배치가 실패하면 해당 봇은 **신규 진입을 멈추고** 알려요
- 이미 걸어둔 증권사 조건 주문(손절)은 취소하지 않고 유지해요
- 실전 포지션은 진입 체결 직후 증권사 조건주문(`SINGLE` + 시장가 매도, 수량 = 봇 보유 수량)으로 손절을 걸어, 서버가 죽어도 손절이 작동하게 해요
  - 이 조건주문은 KRX 정규장에서만 발동해요. 그래서 봇 매매도 정규장으로 한정해요 (POL-RISK-15)
  - 만료일은 당일 청산 봇은 당일, 이월 봇은 최대 보유일까지로 잡아요

## 7-1. 손절 조건주문과 봇 매도의 순서 (POL-RISK-14)

조건주문은 "누구의 주식인지" 모르고 수량만큼 팔아요. 봇이 먼저 팔았는데 조건주문이 남아 있으면 직접 보유한 주식까지 팔 수 있어요.

1. 봇이 매도(익절·청산·수량 축소)하기 전에 **먼저 자기 손절 조건주문을 취소**해요
2. 취소가 확인된 뒤에만 매도 주문을 내요
3. 취소하려는데 이미 발동돼 있으면 매도하지 않고, 조건주문 체결을 그 포지션의 손절 청산으로 기록해요
4. 일부만 매도하면 남은 수량으로 조건주문을 다시 걸어요

## 9. 검증 구간과 상한 해제 (POL-RISK-13)

모의(가상 투자금) 모드는 두지 않아요. 봇은 처음부터 실제 계좌로 매매하고, 대신 **검증 구간** 동안 투자금 상한(POL-RISK-09)을 걸어요. 아래 기준을 **모두** 만족해야 상한을 풀 수 있어요. 화면에서만 막지 않고 서버에서 강제해요 ([FR-BOT-06](../product/features/f1-bot-setup.md)). 결정 근거는 [Q-018](../project/open-questions.md#q-018)에 있어요.

| 기준 | 값 |
| --- | --- |
| 검증 기간 | 10거래일 이상 |
| 청산 거래 수 | 30건 이상 |
| 순손익 (수수료·세금 차감) | 0원 초과 |
| 손익비 | 1.5 이상 |
| MDD | 해당 봇 누적 손실 한도의 절반 이하 |

- 새 봇은 검증 구간으로 시작해요
- 기준은 현재 봇 버전의 검증 구간 기록으로만 계산해요
- **판단이 바뀌는 변경**(종목 필터·진입·청산 규칙 값)은 새 버전이 되고 검증 구간부터 다시 시작해요. 새 버전은 봇이 쉬는 중(보유 종목·미체결 주문이 없고 운영 시간 밖)이면 저장하자마자 적용하고, 아니면 쉬는 중이 되는 첫 시점에 적용해요(당일 청산 봇은 그날 운영이 끝난 뒤). 적용할 때 투자금을 상한으로 다시 확정해요(초과분은 운용 자산으로 반환, POL-FUND-06)
- **위험만 줄이는 변경**(손실 한도 조이기, 연속 손절 횟수 줄이기, 1회 주문 금액 줄이기)은 새 버전으로 기록하지만 검증 기록을 이어 써요. 상한 해제 상태도 유지해요
- 상한을 풀어도 투자금은 그대로예요. 늘리려면 쉬는 중에 투자금을 다시 정해요 (POL-FUND-12)
- 위험만 줄이는 변경도 적용 시점은 판단이 바뀌는 변경과 같아요(쉬는 중이면 바로)
- 실제 돈을 넣기 전 엔진 버그 점검은 사용자 기능이 아니라 개발 단계에서 PaperBroker로 해요 ([ADR-0005](../architecture/adr/0005-in-house-paper-broker.md), [로드맵 M3](../project/roadmap.md#마일스톤))
