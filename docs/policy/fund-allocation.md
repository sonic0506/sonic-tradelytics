# 자금 배분 정책

> 상태: 초안 · 담당: @소닉 · 최종 수정: 2026-10-27
> 관련: [F1 봇 설정](../product/features/f1-bot-setup.md) · [리스크 관리](./risk-management.md) · [용어집](../project/glossary.md)

## 원칙

봇 투자금은 **시작 시점의 운용 자산을 기준으로 한 번 확정**되고, 운용 중에는 절대 바뀌지 않는 고정 예산이에요. 투자금은 운용 자산 대비 비율(정률)이나 금액(정액)으로 정해요. 봇은 여러 종목을 사더라도 이 금액 안에서만 투자해요.

모든 봇은 실제 계좌 돈으로 운용해요(모의 모드 없음, [Q-018](../project/open-questions.md#q-018)). 검증 구간(POL-RISK-13)의 봇도 아래 규칙을 모두 똑같이 따르고, 투자금 상한(POL-RISK-09)만 추가로 걸려요(POL-FUND-11).

## 정책

### 기본

| ID | 정책 | 내용 |
| --- | --- | --- |
| POL-FUND-01 | 같은 기준 시점 | 같은 시각에 시작하는 봇들은 모두 같은 운용 자산 스냅샷으로 배분해요. 예) 09:00 시작 봇은 08:59 시점 금액 기준 |
| POL-FUND-02 | 운용 자산 정의 | `운용 자산 = 주문 가능 금액 − Σ(실행 중인 봇의 현금 몫)`. 주문 가능 금액은 토스 `buying-power`의 `cashBuyingPower`예요(예수금 아님). 직접 보유 주식은 포함하지 않아요 |
| POL-FUND-03 | 비율 합계 검사 | 같은 시점에 시작하는 봇들의 **정률 합이 100%를 넘으면** 저장·시작 불가. 정액을 포함한 총액은 설정 화면에서 현재 운용 자산 기준으로 미리 보여주고 넘으면 경고해요. 실제 시작 시점의 처리는 POL-FUND-14, 15를 따라요 |
| POL-FUND-04 | 금액 고정 | 운용 중에는 입출금, 다른 봇 손익, 주가 변동과 무관하게 확정 투자금 불변 |
| POL-FUND-05 | 한도 내 집행 | 매수 주문 전마다 `보유 종목 매수 금액 + 미체결 매수 주문 금액 + 이번 주문 금액 + 예상 수수료 ≤ 확정 투자금`을 검사하고, 넘으면 주문 차단 |
| POL-FUND-06 | 반환과 재배분 | 봇 종료·중지 시 남은 금액(손익 포함)은 운용 자산으로 반환되고, 다음 시작 시점 스냅샷에 반영 |
| POL-FUND-07 | 이월 봇 처리 | 스윙·종가 베팅처럼 날짜를 넘겨 보유하는 봇은 다음 날에도 확정 투자금 **전체**가 묶여요. 주식으로 산 부분은 이미 주문 가능 금액에서 빠져 있으므로, 다음 날 스냅샷에서는 그 봇의 **현금 몫**만 빼요(POL-FUND-02). 그 결과 "보유 주식 원가 + 현금 몫"으로 확정 투자금 전체가 유지돼요 |
| POL-FUND-08 | 증액 금지 | 어떤 경로로도(재평가 포함) 운용 중 투자금이나 추가 매수 한도를 늘릴 수 없어요 |
| POL-FUND-09 | 늦게 시작하는 봇 | 장 시작 이후 시작하는 봇(예: 15:10 종가 베팅)은 그 시각에 새 스냅샷을 찍고, 그 시점의 운용 자산(POL-FUND-02) 기준으로 배분해요 |
| POL-FUND-10 | 수익 재투자 안 함 | 운용 중 실현 수익은 한도에 더하지 않고 따로 쌓아요. 남은 한도 계산에는 확정 투자금만 쓰고, 쌓인 수익은 봇 종료 시 반환 금액에 포함돼요(POL-FUND-06) |

**봇 현금 몫**은 봇에 묶여 있지만 아직 현금으로 남아 있는 돈이에요.

```
봇 현금 몫 = 확정 투자금 + 실현 손익(수수료·세금 차감) − 보유 종목 매수 금액 − 미체결 매수 주문 금액
```

주식을 사거나 매수 주문을 걸면 그 돈은 이미 주문 가능 금액에서 빠져 있어요. 그래서 확정 투자금 전체가 아니라 현금 몫만 빼야 같은 돈을 두 번 빼지 않아요. 실현 손실이 나면 현금 몫이 줄어, 손실은 그 봇 안에서만 반영돼요(POL-FUND-04).

### 정액·정률 혼합

| ID | 정책 | 내용 |
| --- | --- | --- |
| POL-FUND-13 | 정률 기준 | 정률 봇 투자금 = **스냅샷 운용 자산 전체** × 비율(원 단위 내림). 같이 시작하는 정액 봇의 금액을 먼저 빼지 않아요. 그래서 "운용 자산의 50%"는 다른 봇 구성과 상관없이 항상 같은 뜻이에요 |
| POL-FUND-14 | 확정 순서 | 같은 시각에 시작하는 봇은 ① 정률 봇을 모두 확정하고(합 ≤ 100%라 항상 가능) ② 남은 금액에서 정액 봇을 **시작 우선순위** 순으로 확정해요 ③ 남은 돈은 미배분으로 둬요. 시작 우선순위는 봇마다 정하고, 기본값은 생성 순서예요 |
| POL-FUND-15 | 부족하면 보류 | 정액 봇은 남은 금액이 설정 금액보다 적으면 **줄여서 시작하지 않고** "자금 부족 대기"로 보류하고 알려요(처음 보류될 때 1회). 다음 순서의 정액 봇은 계속 검사해서, 남은 금액 안에 들어가면 확정해요. 보류된 봇은 다음 거래일 장 시작 스냅샷에서 자동으로 다시 시도하고, 사용자가 금액을 줄여 바로 다시 시작할 수도 있어요 |
| POL-FUND-16 | 최소 금액 | 1회 주문 금액이 정액으로 설정된 봇은 확정 투자금이 그보다 작으면 정률·정액 관계없이 POL-FUND-15와 같이 보류해요. 한 번도 주문할 수 없는 봇을 시작하지 않기 위해서예요 |

### 검증 구간 봇

| ID | 정책 | 내용 |
| --- | --- | --- |
| POL-FUND-11 | 검증 구간 투자금 | 검증 구간(POL-RISK-13)의 봇은 POL-FUND-13~15로 계산한 금액과 상한(POL-RISK-09) 중 **작은 값**으로 확정해요. 비율 합계 검사(POL-FUND-03)는 설정 비율 그대로 해요(상한이 풀린 뒤에도 합이 100%를 넘지 않게) |
| POL-FUND-12 | 상한 해제 시 새로 확정 | 상한이 풀리면 사용자가 "투자금 확대"를 눌러요. 그때 기존 투자금을 반환하고(POL-FUND-06) 그 시점 운용 자산 스냅샷으로 **새로 확정**해요(POL-FUND-01~03, 13~16 적용). 운용 중 증액이 아니라 반환 후 재배분이라 POL-FUND-08과 충돌하지 않아요. 보유 종목이 없을 때만 할 수 있어요 |

## 실전 예시

계산을 단순하게 하려고 수수료·세금은 0으로 봐요.

### 예시 1. 정률 봇만, 09:00 시작

08:59 운용 자산 1,000,000원.

| 봇 | 유형 | 설정 | 확정 투자금 |
| --- | --- | --- | --- |
| A | 데이 트레이딩 | 정률 10% | 100,000 |
| B | 스캘핑 | 정률 20% | 200,000 |
| C | 스윙 | 정률 30% | 300,000 |
| 미배분 | | | 400,000 |

### 예시 2. 정률·정액 혼합 + 검증 구간 봇, 자금 충분

08:59 운용 자산 1,000,000원. 정률 합 50%.

| 순서 | 봇 | 유형 | 설정 | 계산 | 확정 투자금 |
| --- | --- | --- | --- | --- | --- |
| ① 정률 | A | 데이 트레이딩 | 정률 20% | 1,000,000 × 20% | 200,000 |
| ① 정률 | B | 스캘핑 | 정률 30% | 1,000,000 × 30% | 300,000 |
| ② 정액 1순위 | C | 데이 트레이딩 | 정액 150,000 | 남은 500,000에서 | 150,000 |
| ② 정액 2순위 | D | 스윙 | 정액 100,000 | 남은 350,000에서 | 100,000 |
| ③ | 미배분 | | | | 250,000 |

B의 30%는 정액 C·D를 뺀 금액이 아니라 운용 자산 전체(1,000,000원) 기준이에요(POL-FUND-13). C가 검증 구간이고 상한이 10만 원이면 C는 100,000원으로 확정되고, 미배분은 300,000원이 돼요(POL-FUND-11).

### 예시 3. 자금 부족, 정액 봇 일부 보류

08:59 운용 자산 500,000원.

| 순서 | 봇 | 유형 | 설정 | 남은 금액 | 결과 |
| --- | --- | --- | --- | --- | --- |
| ① 정률 | A | 데이 트레이딩 | 정률 40% | 500,000 | 200,000 확정 |
| ① 정률 | B | 스캘핑 | 정률 30% | 300,000 | 150,000 확정 |
| ② 정액 1순위 | C | 스윙 | 정액 100,000 | 150,000 | 100,000 확정 |
| ② 정액 2순위 | D | 데이 트레이딩 | 정액 80,000 | 50,000 | **보류** (자금 부족 대기, 알림) |
| ② 정액 3순위 | E | 종가 베팅 | 정액 30,000 | 50,000 | 30,000 확정 |
| ③ | 미배분 | | | 20,000 | |

D가 보류돼도 E는 남은 금액 안에 들어가서 시작돼요(POL-FUND-15). D는 다음 거래일 08:59 스냅샷에서 다시 시도해요.

### 예시 4. 정액 1만 원인데 9천 원 남음

15:10 시작 시점 운용 자산 9,000원.

| 봇 | 설정 | 결과 |
| --- | --- | --- |
| F (종가 베팅) | 정액 10,000 | **보류**. 9,000원으로 줄여서 시작하지 않아요(POL-FUND-15) |
| G (종가 베팅) | 정률 50%, 1회 주문 금액 정액 5,000 | 9,000 × 50% = 4,500원으로 1회 주문 금액보다 작아 **보류**(POL-FUND-16) |

### 예시 5. 이월 봇이 있는 다음 날, 늦게 시작하는 봇

**1일차**

| 시각 | 일 | 주문 가능 금액 | 운용 자산 |
| --- | --- | --- | --- |
| 08:59 | 실행 중 봇 없음 | 1,000,000 | 1,000,000 |
| 09:00 | S(스윙, 정률 30%) 300,000, D(데이 트레이딩, 정률 20%) 200,000 확정 | | |
| 장중 | S가 250,000어치 매수 후 보유. D는 매매 후 실현 +20,000, 장 마감 전 청산·종료 → 220,000 반환 | | |
| 장 마감 후 | | 1,000,000 − 250,000 + 20,000 = **770,000** | |

**2일차**

| 시각 | 계산 | 결과 |
| --- | --- | --- |
| 08:59 | S 현금 몫 = 300,000 + 0 − 250,000 − 0 = 50,000 → 운용 자산 = 770,000 − 50,000 | **720,000** |
| 09:00 | A(데이 트레이딩, 정률 50%) = 720,000 × 50% | 360,000 확정 |
| 장중 | A가 100,000어치 매수 후 보유 (손익 0 가정) → 주문 가능 금액 670,000 | |
| 15:10 | S 현금 몫 50,000, A 현금 몫 = 360,000 − 100,000 = 260,000 → 운용 자산 = 670,000 − 50,000 − 260,000 | **360,000** |
| 15:10 | F(종가 베팅, 정액 200,000) | 200,000 확정, 미배분 160,000 |

검산: 미배분 160,000 + F 200,000 + A 360,000 + S 300,000 = 1,020,000 = 처음 1,000,000 + D 수익 20,000.

## 검증 시나리오

구현 시 아래를 단위 테스트로 고정해요. 위 실전 예시 1~5도 그대로 테스트 케이스로 써요.

1. 같은 시각 시작 봇 3개(10/20/30%)는 같은 스냅샷 id를 쓰고 투자금이 10만/20만/30만 원이다
2. 정률 합 110%면 저장·시작이 거부된다
3. 봇 A가 5만 원 수익을 내도 봇 B의 확정 투자금은 그대로다
4. 보유 8만 + 미체결 1.5만 + 신규 1만 + 수수료로 10만 원을 넘으면 주문이 차단된다
5. 이월 봇(투자금 20만 원, 보유 5만 원)이 있으면 다음 날 스냅샷에서 현금 몫 15만 원이 빠지고, 보유 5만 원과 합쳐 20만 원 전체가 묶인 상태가 유지된다
6. 봇 종료 시 남은 금액이 반환 기록으로 남고, 다음 스냅샷에 포함된다
7. 09:00 봇들이 60%를 배분한 뒤 15:10에 시작하는 봇은 15:10 스냅샷의 운용 자산 기준으로 배분된다
8. 투자금 10만 원 봇이 2만 원 실현 수익을 내도 남은 한도 계산은 10만 원 기준이고, 종료 시 반환 금액에는 2만 원이 포함된다
9. 직접 보유 주식 평가액이나 예수금이 바뀌어도, 운용 자산은 주문 가능 금액으로만 계산된다
10. 상한 10만 원, 정률 30%인 검증 구간 봇은 운용 자산 100만 원에서 10만 원으로 확정되고, 비율 합계 검사에는 30%로 들어간다
11. 검증 구간 봇이 투자금 10만 원으로 3만 원 수익을 낸 뒤 상한이 풀려 투자금을 확대하면, 13만 원이 반환된 뒤 그 시점 스냅샷으로 새로 확정된다
12. 운용 자산 100만 원에서 정률 50% 봇과 정액 30만 원 봇이 같이 시작하면 정률 봇은 50만 원이다 (정액을 뺀 70만 원의 50%인 35만 원이 아님)
13. 정률 합이 100% 이하면 정률 봇은 항상 확정되고, 자금 부족 보류는 정액 봇에서만 생긴다
14. 정액 1만 원 봇은 남은 금액이 9천 원이면 보류되고, 9천 원으로 시작되지 않으며, 다음 거래일 스냅샷에서 다시 시도된다
